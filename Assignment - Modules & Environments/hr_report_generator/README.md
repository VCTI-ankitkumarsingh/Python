# Project 1 – HR Report Generator

This project demonstrates Python modules, a Python package, third-party libraries, virtual environment isolation, and dependency management for an HR employee reporting application.

## Libraries Used

Project 1 uses the following third-party libraries:

- **Jinja2** – generates employee reports from a predefined template.
- **PrettyTable** – creates a formatted ASCII employee table.

> **Note:** Rich and Tabulate belong to Project 2 and are not used in this project.

---

## Part 1 – Project 1 Output

The application is executed using:

```bash
python app.py
```

The output contains:

1. An HR employee report generated using the **Jinja2 template**.
2. Employee details such as ID, name, department, and salary.
3. A formatted employee table generated dynamically using **PrettyTable**.

## Part 3 – Comparing the Libraries

For this project, the two required libraries have different responsibilities.

| Library | Purpose | Outcome |
|---|---|---|
| Jinja2 | Template-based report generation | Dynamic employee report text |
| PrettyTable | Employee table formatting | ASCII box-style table |

### Why Jinja2?

Jinja2 is suitable when a fixed report format is required and the employee information changes dynamically. The employee data is inserted into `templates/employee_report.txt` using Jinja2 template syntax.

### Why PrettyTable?

PrettyTable is suitable for creating a clean, readable table directly in the terminal. The employee records are added dynamically, and the library handles the table borders and alignment.

### Part 3 Outcome

Jinja2 is used for **report/template generation**, while PrettyTable is used for **formatted employee table generation**. Together, they satisfy the HR Report Generator requirements.

## Part 4 – Virtual Environment Isolation

A separate virtual environment is used for Project 1:

```text
hr_report_generator/
└── .venv/
    ├── Jinja2
    └── PrettyTable
```

The environment is created and activated using:

```bash
python -m venv .venv
.venv\Scripts\activate
```

The installed packages can be checked using:

```bash
pip list
```

The Project 1 environment contains Jinja2 and PrettyTable, while libraries belonging to Project 2 are not installed in this environment.

### Test 1 Screenshot

**Test 1** contains the results of the Project 1 environment verification.

It shows:

- `prettytable 3.16.0`

### Part 4 Outcome

The Project 1 application runs inside its own `.venv`, with Jinja2 and PrettyTable installed independently of the other project's environment.

## Part 5 – Proving the Environments Are Separate

The isolation was verified by checking for packages that belong to the other project.

With the Project 1 environment active:

```bash
pip show rich
pip show tabulate
```

The result was:

```text
WARNING: Package(s) not found: rich
WARNING: Package(s) not found: tabulate
```

At the same time, `pip list` confirmed that the Project 1 dependencies are installed:

```text
Jinja2       3.1.6
prettytable  3.16.0
```

### Part 5 Outcome

The results demonstrate that installing libraries for Project 1 does not automatically make the other project's libraries available in the Project 1 environment.

Therefore, the environments provide dependency isolation between the two projects.
